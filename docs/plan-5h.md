# План на 5 часов

T — время от официального старта. Кейс рекомендует 30 минут на роли, стек и схему данных. Всё это уже решено в `docs/`, поэтому эти 30 минут уходят на каркас.

Две дорожки идут параллельно:
- **A — ты:** backend и ML. Руками работают AI-агенты: **Cursor (A1)** — ядро backend, **Codex (A2)** — AI и ML. Ты ставишь задачи, проверяешь, сливаешь.
- **B — друг:** frontend, UX и демо. Работает со своим AI-агентом.

До готовности backend B работает на моках по `docs/api-contract.md`, поэтому никто никого не ждёт.

- [ ] Выбран **демо-ноутбук**: на нём финальный прогон и защита. По умолчанию — ноутбук A.

## 2. Git-процесс

```text
main                 ← интеграция; сюда сливаем на S1, S2, S3 и в финале
├── feat/backend-core   ← A1 (Cursor), основная папка D:\projects\hakaton
├── feat/ai-ml          ← A2 (Codex), worktree ..\hakaton-ai
└── feat/frontend       ← B, ноутбук друга
```

- Первым делом документация коммитится и пушится в `main`. Иначе ни worktree, ни клон у B её не увидят.
- Worktree для Codex, чтобы агенты не мешали друг другу: `git worktree add ..\hakaton-ai -b feat/ai-ml main`. Каркас backend вливается туда через `git merge feat/backend-core` около 0:20.
- **Зоны не пересекаются** (`AGENTS.md`, раздел 3), поэтому конфликтов почти нет. Общие файлы (`docs/`, `.env.example`, `pyproject.toml`) меняет один человек, предупредив другого.
- **Push только по решению человека.** Агенты сами не пушат.
- Коммиты — со своих GitHub-аккаунтов. Это доказательство личного вклада, которого требуют правила.
- Сообщения коммитов: `feat(backend): ...`, `feat(ai): ...`, `feat(frontend): ...`, `fix: ...`, `docs: ...`.
- Перед каждым push — проверка на секреты (команда в `AGENTS.md`).
- Force-push в `main` запрещён.

## 3. Cut-list: что режем, если не успеваем

Режем сверху вниз:

1. Своя модель на Brev. Build API для +7 недоступен (`docs/nvidia-brev.md`), так что без Brev NVIDIA останется только в питче. Режем, если к T+2:30 модель не поднялась.
2. Eval-стенд (оставляем 3–4 ручных примера в README).
3. Дубликаты, модерация NemoGuard, лидерборд заказчиков, RU/KZ, конфетти.
4. Эмбеддинги в рекомендациях → только TF-IDF и совпадение навыков.
5. История рейтинга графиком → только число `delta`.
6. Этапы и лидерборд команд → одна кнопка «Подтвердить этап (+10)».

**Никогда не режем:** черновик и не меньше 3 вопросов; редактируемую карточку с подтверждением; рейтинг 0–100 с расшифровкой и пересчётом; уровни; каталог с сортировкой и фильтрами; отклик; ручное решение бизнеса; офлайн-заглушку; README.

## 4. Риски

| Риск | Защита |
| --- | --- |
| Упала сеть или API; раздавать интернет запрещено | Цепочка провайдеров и заглушка, TF-IDF. Сценарий работает офлайн. Перед демо проверяем `AI_PROVIDER=stub` |
| Модель вернула невалидный JSON | Pydantic, один repair, следующий провайдер, заглушка. Всё видно в AI Inspector |
| Модель выдумала факт | Grounding-guard: цитаты, числа, контакты. На демо это аргумент, а не проблема |
| Фронт и бэк разъехались | Контракт в `docs/api-contract.md`, типы из `/openapi.json`, синхронизации S1–S3 |
| Агенты правят одни файлы | Зоны ответственности и worktree |
| Brev долго поднимается | Стартуем в T+0:10, дедлайн T+2:30, потом бросаем |
| Демо сломалось на защите | Кнопка «Сбросить демо», отрепетированный сценарий, готовые тексты ответов, офлайн-режим, запасная запись экрана |
| Утечка ключа | `.env` в `.gitignore`, проверка перед push, при утечке — отзыв ключа и сообщение организаторам |
| Нарушили правила площадки | Оба в зале весь последний час; выходы не больше 60 минут суммарно; у каждого свои коммиты |
