# Роль B — Frontend, UX и демо (друг)

Ты отвечаешь за всё, что видит жюри: интерфейс, геймификацию на экране и само демо. Код пишет твой AI-агент (Codex или Cursor), ты ставишь задачи и проверяешь в браузере. Твоя зона — `frontend/`, твои коммиты — твой личный вклад, которого требуют правила.

Что на тебе:
1. Весь UI сквозного сценария для ролей «Бизнес» и «Команда».
2. Геймификация на экране: кольцо рейтинга, уровни, подсказки «+N», ачивки, история, место в каталоге. Это визуальная половина самого дорогого критерия (25 баллов).
3. AI Inspector — экран прозрачности AI.
4. Демо: ведёшь его, репетируешь, делаешь запасную запись (`docs/demo-script.md`).
5. Скриншоты для README и текст описания для платформы.

## 1. Настройка

```powershell
git clone https://github.com/BAITC-Hacks/hack-4b695b60-ai-just.git hakaton
cd hakaton
git checkout -b feat/frontend

npm create vite@latest frontend -- --template react-ts
cd frontend
npm install
npm install tailwindcss @tailwindcss/vite
npx shadcn@latest init
npx shadcn@latest add button card badge progress tabs dialog sheet textarea input select tooltip table skeleton alert sonner separator label checkbox popover accordion dropdown-menu
npm install @tanstack/react-query react-router recharts motion lucide-react canvas-confetti
npm install -D openapi-typescript @types/canvas-confetti
```

- В `vite.config.ts`: плагин `@tailwindcss/vite`, алиас `@ → ./src` (нужен для shadcn), proxy `server.proxy = { "/api": "http://localhost:8000" }`.
- В `package.json`: `"gen:api": "openapi-typescript http://localhost:8000/openapi.json -o src/api/schema.d.ts"`.
- В `frontend/.env.local`: `VITE_USE_MOCKS=true` до S1, потом `false`. **Ключей во frontend нет: всё с `VITE_` видно в браузере.**
- Backend у себя поднимаешь без ключей, когда A запушит: `cd backend; uv sync; uv run uvicorn app.main:app --port 8000`. AI работает в офлайн-режиме, этого хватает для UI. Нужен uv: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`, или `docker compose up backend`, когда появится compose-файл.

## 2. Экраны и критерии приёмки

Подписи полей, критериев, уровней и тем берём из `GET /api/meta`, а не хардкодим. Формы данных — в `docs/api-contract.md`.

### 2.1 Каркас

- Шапка: «AI Sana Challenge Hub», переключатель роли **Бизнес** (выбор из `/api/businesses`) и **Команда** (выбор из `/api/teams`). Роль хранится в `localStorage`.
- Навигация бизнеса: «Новая задача», «Мои задачи», «Каталог», «Лидерборд». Навигация команды: «Каталог», «Рекомендации», «Мои отклики», «Лидерборд».
- Бейдж AI-провайдера из `/api/health` (OpenAI, NVIDIA, Brev, Офлайн). По клику меню переключения через `PUT /api/ai/provider`, там же «Сбросить демо» (`POST /api/admin/reset`).

### 2.2 Конструктор задачи (бизнес) — мастер из 4 шагов

1. **Черновик:** textarea (плейсхолдер — пример слабого текста), выбор темы, кнопка «Проанализировать». Пока AI думает — скелетон «AI читает черновик…».
2. **Уточнение:** вопросы (не меньше 3), у каждого чип поля, бейдж «+N баллов», строка «зачем», поле ответа; можно пропустить. Сбоку — «AI нашёл в тексте» с цитатами. Кнопка «Собрать карточку».
3. **Карточка:** 10 полей. У каждого статус-чип «Пусто», «Предложено AI» или «Подтверждено». По наведению на «Предложено AI» — цитаты-доказательства и источник. Действия у поля: «Подтвердить», «Отклонить», правка на месте (сохранённая правка становится `confirmed`). Кнопки «Подтвердить всё» и «Задать ещё вопросы» (`/clarify`). Справа — панель рейтинга (2.3).
4. **Публикация:** диалог с чекбоксом «Я проверил карточку»; предупреждение «N полей не подтверждены и не попадут в карточку». После публикации — экран успеха: место в каталоге, уровень, конфетти при уровне «Приоритетная».

Готово, когда черновик из `docs/demo-script.md` проходит все 4 шага без перезагрузки страницы.

### 2.3 Панель рейтинга — главный экран геймификации

| Элемент | Данные | Поведение |
| --- | --- | --- |
| Кольцо готовности 0–100 | `rating.score`, `rating.level` | Цвет уровня, анимированный счётчик, всплывающее «+N» из `rating.delta` |
| Уровень и прогресс | `rating.level`, `rating.next_level` | «Готовая · до «Приоритетной» 14 баллов» и полоска |
| Потенциал AI | `potential_score − score` | «AI нашёл ещё +31 — подтвердите 4 поля» с кнопкой «Подтвердить всё» |
| Расшифровка | `rating.breakdown` | Аккордеон по 7 критериям: `earned/max` и проверки с галочками и баллами |
| Что поднимет рейтинг | `rating.missing` (топ-3) | «+10 · Укажите ограничения…»; по клику — фокус на нужное поле |
| Место в каталоге | `catalog_position_preview` | «Если опубликовать сейчас — №2 из 7» |
| Ачивки | `rating.achievements` | 8 значков, серые до получения; тост при получении |
| История | `GET /api/tasks/{id}/history` | Мини-график Recharts 27 → 76 → 96 |

Цвета уровней: Черновик — `slate`, Рабочая — `sky`, Готовая — `emerald`, Приоритетная — `amber` со свечением. Статусы полей: пусто — приглушённый, предложено AI — `violet`, подтверждено — `emerald`.

### 2.4 Каталог (все роли)

- Фильтры: тема, уровень (переключатели, можно несколько), поиск; сортировка «По рейтингу» или «Новые».
- Карточка задачи: номер позиции, название, бизнес, тема, бейдж уровня, балл, превью потребности, число откликов. У `highlighted` золотая рамка; у `needs_clarification` приглушённый вид и бейдж «Требует уточнения».
- Пустое состояние и ошибка загрузки.

### 2.5 Страница задачи и отклик (команда)

- Публичная карточка (только подтверждённые поля) и расшифровка рейтинга только для чтения.
- «Откликнуться» (роль «Команда»): идея, план, срок, ссылка на прототип. Валидация как на backend: идея и план от 20 символов, ссылка `http(s)`. Тост об успехе.

### 2.6 Рекомендации (команда)

Карточки с `match` в процентах, причинами и чипами совпавших навыков. Бейдж метода (NVIDIA embeddings или TF-IDF). Всегда видна подпись «Рекомендации не ограничивают каталог» со ссылкой на каталог.

### 2.7 Кабинет бизнеса: мои задачи и отклики

- «Мои задачи»: список с баллом, уровнем, статусом и числом откликов.
- Вкладка «Отклики (N)»: карточки откликов — команда с чипами навыков, идея, план, срок, ссылка; нейтральный чек-лист полноты (идея, план, срок, ссылка). Кнопки «Выбрать» и «Отклонить» с комментарием по желанию. Подпись: «Решение принимает только бизнес. Система не назначает команды».
- Для выбранного отклика — «Этапы»: добавить (название, баллы 5–30), «Подтвердить» → тост «+10 баллов команде Nomad AI».

**Никакой сортировки откликов «по качеству» и никаких пометок «лучший»:** это нарушит правило «AI не выбирает за бизнес».

### 2.8 Лидерборд

Команды по баллам прогресса: место, название, баллы, подтверждённые этапы. P2 — вкладка «Заказчики» по среднему рейтингу задач.

### 2.9 AI Inspector (боковая панель)

Открывается кнопкой «Как это работает» на странице задачи.
- Список вызовов: провайдер, модель, версия промпта, задержка, статус (`ok` зелёный, `repaired` жёлтый, `fallback` оранжевый).
- В развороте: замаскированный вход, сырой ответ (моноширинно), распарсенный JSON, ошибки валидации, отклонённые grounding-проверкой поля красным («Отклонено: число 15 не найдено в тексте»).
- Вкладка «Промпты и схемы» из `/api/ai/prompts`.

### 2.10 Model Lab (P2)

Таблица метрик eval по провайдерам из `GET /api/ai/eval/latest`.

## 3. Моки до готовности backend

`src/api/client.ts` — единая точка. При `VITE_USE_MOCKS=true` функции отдают фикстуры из `src/api/mock/` в формате контракта. Для конструктора достаточно заготовленных снимков `TaskDetail` на 4 шага (рейтинг 27, 76, 96, 100): так видна анимация роста. На S1 переключаешься на реальный API и прогоняешь `npm run gen:api`.

## 6. Как проверять работу агента

- [ ] `npm run dev` открывается без ошибок в консоли браузера.
- [ ] `npm run build` и `npx tsc --noEmit` проходят.
- [ ] Сценарий из `docs/demo-script.md` проходит на реальном backend (после S1).
- [ ] У каждого запроса есть состояние загрузки и понятная ошибка на русском.
- [ ] Нигде нет ключей и захардкоженных URL, кроме `/api`.
- [ ] Отклики не ранжируются и не помечаются «лучший».
